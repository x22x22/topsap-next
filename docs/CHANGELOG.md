### 修复

- 登录、短信登录、改密与找回密码的账号/密码字段改为 Base64（对齐官方客户端 3.6.6.19）；无图形验证码时不再发送空 `Gid`，修复本地账号首次登录被网关误报 `-40081`、无法进入改密流程的问题
- 登录 User-Agent 保持无 `VERSION` 后缀；官方客户端的版本后缀未观察到参与登录校验，避免在 macOS/Linux 上声明为特定的 Windows 客户端版本
- 登录验证码策略按原客户端 `auth_param.gid`（`on`/`auto`/`off`）与 `login_check_verify` 解析；`auto` 模式在 `login_err_num >= 3` 后自动要求图形验证码，失败次数按账号跨连接保留
- `-40081` 附带密码状态文本时转入改密窗口：网关 `ErrMsg` 明确提到密码到期、首次登录、初始密码或管理员要求改密时，映射为对应返回码并弹出改密窗口；普通凭据错误仍保持原提示
- 凭据错误优先展示网关 `ErrMsg`，不再被固定的「账号或密码错误」掩盖
- 忘记密码重置成功后自动把新密码带回登录表单；切换账号时清除上一个账号自动填入的密码，避免用旧密码登录报 `-40081`
- 补齐登录改密提示（密码到期、过弱、首次登录、管理员要求改密）与「需要修改密码后才能登录」的中英文映射；新增文案同步检查规范
- 自动重连日志去掉「（等待 N 秒）」：该文案在每次重连尝试前打印，与实际重连耗时不一致
- 找回密码成功提示补充「新密码已自动填入」，与登录框自动回填行为一致
- 网卡自检：切换页面后保持运行与按钮旋转状态；每一步完成后立即展示；开始前清理上次残留的 `TopSAP` 虚拟网卡，修复 `Win32 1247` 与残留网卡；增加并发运行保护
- macOS：路由改为 `route -n add -net <dest> -netmask <mask> <VIP>` 并回读接口；DNS 通过 `networksetup` 按「VPN DNS 在前、原 DNS 在后」写入当前网络服务，断开时恢复原列表或自动获取；helper 增加 `networksetup` 白名单并独立版本号以触发重装
- Linux / macOS 自检：Unix TUN fd 改为非阻塞，读线程改为每轮 `poll` 后最多读取 32 个报文并用 `try_send` 投递；`reader.join()` 不再阻塞异步任务，自检结束能正常清理路由与网卡
- Linux 自检残留：开始前仅删除带自检地址 `10.99.99.2` 的 `topsap0`，避免误删正在使用的连接网卡；自检运行中拒绝连接，连接流程中或存在待清理资源时拒绝自检
- Linux TUN 错误提示：`EPERM/EACCES` 提示需要 root 并给出 `sudo <当前exe>` 命令；`EBUSY` 提示 `topsap0` 被占用并给出 `sudo ip link del topsap0`，不再混用同一条「特权 helper」提示
- Linux 未提权启动：普通用户双击启动时弹窗提示改用 `sudo /usr/bin/topsap-client`；Linux 自检与网卡配置文案移除「系统授权框 / helper」，macOS 保持原提示
- 记住密码：`keyring` 补齐 `apple-native`、`sync-secret-service` 与 `crypto-rust` 后端，修复 Linux / macOS 因退化为进程内 mock 导致「保存成功但重启读不到密码」的问题；CI 增加 `libdbus-1-dev` / `pkg-config`
- 记住密码说明统一为「系统安全存储」，避免在 Linux / macOS 上仍显示「系统凭据管理器」
- macOS 自检接收方向：注入的 ICMP 请求改为「测试网段地址 → 本机 VIP」，由系统生成回包并经测试路由回到 utun；修复 macOS 上因目标非本机、内核不回包导致的「接收方向失败」
- macOS DNS：原 DNS 为自动获取、`networksetup -getdnsservers` 为空时，读取 `scutil --dns` 的默认接口解析器（含 IPv6），仍为空则回退 `networksetup -getinfo` 的 `Router`，按「VPN DNS + 原 DNS」写入；helper 增加 `scutil --dns` 白名单并升级版本以触发重装
- macOS 路由：回读同时比对 `route -n get` 的 `destination` 与 `mask`，修复被 `/24` 覆盖的 `/32` 与 `/31` 被误判为已存在而跳过的问题；删除路由失败时再按 VIP 网关形式补删一次
- 英文映射补齐：macOS helper 未运行、网卡地址配置失败、Windows 虚拟网卡/会话创建失败（含 Win32 提示）、`设置网卡地址失败` 的尝试轮次、Linux/通用 TUN 创建失败、hosts 读写失败；自检明细未命中专用句式时回退到通用后端错误映射
- 网卡自检：去掉 45 秒全局超时，改为管理员、残留清理、建卡、配置地址、注入路由、ping、读线程回收与清理等每个步骤独立 60 秒超时；超时只标记当前步骤失败并继续清理，被取消的系统命令随 future 结束，避免残留 `netsh`/`route` 占用网卡
- macOS DNS：原 DNS 只追加 IPv4，忽略 `scutil --dns` 返回的链路本地 IPv6；断开时仍按原列表或 `Empty` 恢复
- macOS 路由：回读改用网段内主机地址并重试一次，以回读结果判定是否生效，修复路由实际已存在（`route add` 返回非零）时误报「未生效」的问题
- macOS 代理绕过：改为经 privileged helper 执行 `networksetup`，修复普通用户写入 `-setproxybypassdomains` 失败且仅记录日志的问题；helper 白名单新增 `-getproxybypassdomains` / `-setproxybypassdomains`，服务名与条目按既有规则校验，`HELPER_VERSION` 升至 `1.2.3`

## 1.1.0

### 新增

- 异常退出会话补偿：登录成功后加密记录网关、端口与 `session_id`；强杀、崩溃或断电后，下次启动/连接前自动补注销，降低 `Ret=-40077` 单点冲突
- 关机前限时断开：Windows `WM_ENDSESSION`、Linux/macOS `SIGTERM`/`SIGINT` 与 macOS `RunEvent::Exit` 最多等待 2 秒完成断开与注销，超时后交由系统回收 TUN 网卡与路由
- 连接建立失败后主动注销已登录会话，避免残留会话占用单点名额
- 已登录自动踢出：登录返回 `-40077` 时重新获取 `auth_param`，通过 `user_pswd_r`（`U/HASH/S_CODE`）踢出旧会话并继续登录；不依赖本地会话标记，覆盖官方客户端异常退出场景
- macOS 特权 helper：首次启动通过系统授权框安装 root LaunchDaemon（`com.topsap.next.helper`），GUI 保持用户身份；helper 创建 utun 并通过 `SCM_RIGHTS` 传回 fd，只执行 `ifconfig`/`route` 白名单命令，自检与建卡均通过 helper 完成

### 变更

- 断开流程中注销请求与路由清理改为并发执行，缩短异常网络下的断开耗时
- README、架构文档与诊断说明同步异常退出补偿边界、`-40077` 自动踢出与 macOS 提权行为

### 文档

### 兼容性

- 支持 Windows 7 SP1 / Windows 10 / Windows 11（x64）
- 支持 Windows 11 / 10 ARM64：使用 `wintun-arm64.dll`，安装包与便携包按架构选择驱动
- Windows 7 通过 `RtlGetVersion` 运行时检测（版本 6.1），自动切换到 `netsh` 兼容路径，不依赖 PowerShell 3.0+ 的 NetTCPIP 模块；Windows 10/11 保持原有配置逻辑
- Windows 7 需预装 WebView2 Runtime 109 与 Visual C++ 2015-2022 Redistributable
- 支持 macOS（Intel / Apple 芯片）与 Linux（amd64 / arm64）：使用系统 TUN 设备（`tun` crate），通过 `ip` / `route` / `ifconfig` 配置地址与路由，需要 root 或 `sudo`
- macOS 应用未签名与公证，首次打开需移除 Gatekeeper 隔离属性
