# v1.2.0

发布日期：2026-11-04

## 概述

TopSAP Client v1.2.0 是登录协议兼容性修复版本。本版依据官方客户端 3.6.6.19.64.1 的原生日志，修正了登录、短信登录、修改密码与找回密码的账号/密码编码方式，恢复本地账号首次登录的改密流程；同时补齐图形验证码策略、密码状态识别、重置后新密码回填与账号切换密码清理。本版不涉及隧道与数据面改动。

## 修复

### 登录协议与 Base64 编码

- 官方客户端 3.6.6.19.64.1 的 `U/P` 是账号/密码的 Base64（再按表单 URL 编码）。此前发送明文，导致本地或临时账号被网关误判为 `-40081`「用户不存在或密码错误」，无法进入首次登录改密流程
- 无图形验证码时不再发送空 `Gid`，改为官方格式 `U/P/HASH/S_CODE`
- 登录 Cookie 的 `sv_un` 改为账号 Base64
- 短信验证码登录的 `U` 改为账号 Base64
- 修改密码的 `P1/P2` 改为原/新密码 Base64，Cookie 的 `sv_un` 改为账号 Base64
- 找回密码第二步的 `P` 改为新密码 Base64，修复重置后新密码与登录密码不一致的隐患
- User-Agent 保持无 `VERSION` 后缀，避免在 macOS/Linux 上声明为特定的 Windows 客户端版本

### 图形验证码策略

- 按 `auth_param.gid`（`on`/`auto`/`off`）与 `login_check_verify` 解析验证码策略，不再只读取数字型 `captcha`
- `gid=auto` 时，登录失败次数 `login_err_num` 达到 3 次后自动要求图形验证码
- 失败次数写回 Cookie 并按账号跨连接保留，登录成功后清零
- 验证码错误自动刷新，最多重试 4 轮

### 密码状态与登录错误

- 登录返回 `-40022/-40023/-40024/-40199` 时继续弹出无会话改密窗口
- `-40080/-40081` 的 `ErrMsg` 明确提到密码到期、首次登录、初始密码或管理员要求改密时，映射为对应改密返回码并弹窗
- 凭据错误优先展示网关 `ErrMsg`，不再被固定的「账号或密码错误」掩盖

### 找回密码与登录表单

- 忘记密码重置成功后自动把新密码填回登录框，可直接点击连接
- 切换账号时清除上一个账号自动填入的密码，避免用旧密码登录报 `-40081`
- 补齐登录改密提示（密码到期、过弱、首次登录、管理员要求改密）与「需要修改密码后才能登录」的中英文映射

### 日志

- 自动重连日志去掉「（等待 N 秒）」，避免与实际重连耗时不一致

## 验证

- `cargo fmt --check` 通过
- `cargo clippy --all-targets -- -D warnings -A deprecated` 通过
- `cargo test --lib` 通过：141 项
- `npx tsc --noEmit` 通过
- `npm test` 通过：4 个测试文件、31 项用例
- `npm run tauri build` 通过，生成 NSIS 安装包
- 登录报文已与官方客户端原生日志逐字段比对；尚未在真实网关完成首登改密全流程回归

## 安装

- Windows 安装包：`TopSAP Client_1.2.0_x64-setup.exe`，支持 `/S` 静默安装
- Windows 便携版：保留 `resources/wintun.dll` 相对路径，以管理员身份运行
- macOS：首次启动按提示授权安装 root helper；未签名与公证，首次打开需处理 Gatekeeper
- Linux：需 `sudo` 启动，安装 WebKitGTK 4.1 运行时

## 已知限制

- Base64 登录协议依据官方客户端 3.6.6.19.64.1 的原生日志；更老或更新的网关版本可能存在字段差异，需要以抓包为准
- macOS / Linux 与 Windows 共用登录协议代码，但数据面仍未完成真机连接回归
- TUN/透明代理无法使用系统代理绕过；仅支持 `ngvone` / `cipher_type=0` 网关
- 英文模式已覆盖界面文案与常见错误，但网关动态下发的 `ErrMsg` 与后端低层系统错误仍可能显示中文原文
- 连接日志面板展示后端原始中文日志，不随界面语言切换
