# v1.4.1

发布日期：2026-11-07

## 概述

TopSAP Client v1.4.1 是自动更新功能版本。Windows / macOS 更新弹窗新增「自动更新」：从 NAS 发布目录读取版本与安装包，下载后断开 VPN，退出并由平台 helper 替换程序、重启客户端。Windows 使用 PowerShell 2.0 兼容脚本替换 `exe + resources`，macOS 挂载 dmg、校验签名并替换 `.app`；目标目录不可写时请求管理员授权。本版仍按需求不做更新包哈希校验，Linux 保持「前往」手动下载。

## 新增

### Windows / macOS 自动更新

- 版本检查仍读取 NAS `version` 文件；发现新版本后，按平台与架构拼接安装包地址：
  - Windows amd64：`/Windows/topsap-client_<版本>_windows_amd64.zip`
  - Windows arm64：`/Windows/topsap-client_<版本>_windows_arm64.zip`
  - macOS Intel：`/Mac/TopSAP.Client_<版本>_x64.dmg`
  - macOS Apple 芯片：`/Mac/TopSAP.Client_<版本>_aarch64.dmg`
- 更新流程：下载 → 结构准备 → 断开 VPN → 启动 helper → 主程序退出 → 替换 → 重启。
- **先下载、后断开**：NAS 可能只能经 VPN 访问；下载与结构准备完成后再调用 `engine.disconnect()`。断开后仍有未清理网络配置时取消更新并保持运行。
- Windows：
  - 使用 `reqwest` 下载 ZIP，Rust 解压（不依赖 Win7 不支持的 `Expand-Archive`）；
  - 校验 `topsap-client.exe` 与对应架构的 `resources/wintun*.dll`；
  - 生成 UTF-16LE 编码的 PowerShell 2.0 兼容 helper，等待父进程退出；
  - 备份 `topsap-client.exe` 与 `resources/`，替换前删除旧 `resources/`，避免嵌套成 `resources\resources`；
  - 复制失败时回滚并启动旧版本；新程序启动成功后再清理备份与暂存目录；
  - 启动隐藏的 `cmd` 进程，延迟约 2 秒删除整个 `%TEMP%\topsap-update`，不依赖新版本是否带清理逻辑。
- macOS：
  - 下载 dmg 后以只读方式挂载，查找 `.app` 并 `ditto` 到暂存目录；只遍历真实目录、不跟随 DMG 内的 `Applications` 符号链接；
  - 无论复制成功失败都执行 `hdiutil detach -force`；
  - `codesign --verify --deep --strict`；未签名时尝试 ad-hoc 签名并再次校验；有 `com.apple.quarantine` 时移除；
  - helper 等待父进程退出，旧 `.app` 改名为 `.app.old`，复制新包；复制失败回滚；
  - 目标父目录不可写时通过 `osascript ... with administrator privileges` 请求管理员授权；用户取消则返回错误并保持应用运行；
  - 打开新应用成功后删除 `.app.old`、暂存包与临时目录；打开失败则回滚并保留临时目录用于排查；
  - root 场景 `chown` 回原用户，并用 `launchctl asuser` 打开新版本。
- 主程序在 helper 启动后延时 600 ms 调用 `app.exit(0)`；新版本启动时 `cleanup_temp()` 再兜底清理一次临时目录。
- 下载过程通过 Tauri `Channel<UpdateProgress>` 推送阶段与进度：下载、校验、断开、安装、重启。
- 更新包为空、ZIP 魔数错误、缺少 exe 或 `wintun*.dll`、dmg 挂载失败、签名失败、管理员取消等错误均有中英文提示。

### 更新弹窗

- Windows / macOS 更新弹窗新增「自动更新」按钮；Linux 保持「前往」手动下载。
- 「前往」按钮新增独立的青色描边配色，与灰色「稍后」、渐变填充的「自动更新」区分。
- 更新中禁用弹窗关闭与按钮，展示下载百分比/已下载大小、校验、断开、安装与重启阶段；失败显示原因。
- 手动下载文案修正为先点击「前往」打开下载页面，再完整退出当前程序后安装，避免退出后无法点击「前往」。

## 变更

- `update.rs` 拆分为 `update/{mod,download,install}.rs`：版本检查、流式下载与多平台安装分文件维护。
- 新增依赖 `reqwest`（rustls-tls）与 `zip`（仅 deflate，减小体积与编译依赖）。
- 自动更新使用正常证书校验的 HTTPS，不复用网关登录的 `NoVerifyVerifier`。
- README、架构说明与更新记录同步自动更新、按钮配色与临时目录清理说明。

## 修复

- Windows helper 修正替换顺序：先启动新程序，再清理暂存与备份；清理失败使用 `-ErrorAction SilentlyContinue`，不会在新程序已启动后触发回滚覆盖。
- Windows 回滚恢复 `resources` 前先删除目标目录，避免 PowerShell 把备份目录嵌套成 `resources\resources`。
- macOS 挂载失败路径统一 `hdiutil detach -force`，避免 dmg 残留挂载。
- 下载到 0 字节文件时直接报错，不再进入解压/挂载流程；Windows 额外校验 ZIP 魔数。
- 更新弹窗手动下载顺序文案修正，中英文同步。

| Windows 11 / 10 ARM64 | 已实现，CI 构建 `wintun-arm64.dll` 版本；NAS 需补传对应 zip 后才能自动更新 |

| Linux amd64 / arm64 | 不显示「自动更新」，保持「前往」手动下载；数据面不受影响 |

- Windows 安装包：`TopSAP Client_1.4.1_x64-setup.exe`，支持 `/S` 静默安装
- Windows ARM64：`TopSAP Client_1.4.1_arm64-setup.exe`

- Linux：`topsap-client_1.4.1_amd64.deb` / `arm64.deb` / `amd64.rpm` / `arm64.rpm`

自动更新使用注意：

- NAS `version` 文件需更新为高于客户端当前版本的版本号，并上传对应平台安装包；
- Windows 自动更新下载的是便携版 zip，macOS 下载的是 dmg；文件名必须与上述规则一致；
- 当前 NAS 的 Windows arm64 zip 返回 0 字节，需补传真实文件；
- 自动更新仅 Windows / macOS 提供；macOS 应用需位于「应用程序」目录，不能从 dmg 或 App Translocation 位置更新。

## 已知限制

- 按需求不做 SHA-256 / 签名校验：分享目录被篡改时可下发任意文件，这是已知风险；HTTPS 证书校验正常启用。
- macOS 自动更新全流程未真机验证：dmg 挂载、ad-hoc 签名、quarantine 移除、管理员授权弹窗与 `launchctl asuser` 打开应用需要在 Intel / Apple 芯片真机回归。
- Windows 7 自动更新未真机验证：PowerShell helper 按 2.0 语法编写，仍需 Win7 SP1 实测。
- NAS 当前 `version` 仍为 `1.4.0`，且 Windows arm64 包为空；发布 1.4.1 后需上传各平台产物并更新版本文件，自动更新才会实际触发。
- 回滚覆盖复制、挂载、签名失败等命令级失败，不覆盖替换过程中断电或系统崩溃；macOS 极端情况下可能留下 `.app.old`，Windows 可能留下 `update-backup/`。
- macOS 管理员授权弹窗出现前 VPN 已断开；用户取消授权后需要手动重新连接。
- macOS 应用未签名与公证，Gatekeeper 处理方式见安装说明。
- 自动重连当前只重新建立 TLS，不会重新注入路由或重配地址 / DNS；上行泵仍绑定旧隧道句柄的问题待单独修复。
- 断开时 Wintun 适配器只关闭会话 / 句柄，不删除网卡；地址与 DNS 保留在适配器上，下次连接覆盖。
- 仅支持 `ngvone` / `cipher_type=0` 网关；英文模式下的网关动态 `ErrMsg` 仍可能显示中文原文。
