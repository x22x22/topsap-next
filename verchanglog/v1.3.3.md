# v1.3.3

发布日期：2026-11-06

## 概述

TopSAP Client v1.3.3 是 Windows 连接性能与路由实现版本。本版把 Windows 配址从 PowerShell 路径改为纯 `netsh` + 100ms 轮询，并把资源路由从批量 `cmd` / `route.exe` 改为 IPHLPAPI `CreateIpForwardEntry`；NextHop 与官方 Windows 客户端对齐为 **VIP-1**，查重与回读改为比较 `Dest / Mask / NextHop / IfIndex`，Metric 保持 1。macOS / Linux 数据面不变，v1.3.2 的 macOS 修复继续保留。

## 变更

### Windows 配址性能

- 接口索引与地址回读统一使用 `netsh`，移除 `Get-NetAdapter`、`Get-NetIPAddress`、`New-NetIPAddress`
- 地址配置最多三轮：`netsh set address` / `netsh delete+add` / `netsh set address`
- Win10/11 改为 100ms 短间隔轮询，地址出现立即继续；不再固定等待 600ms
- Win7 保持 600ms 固定等待与 `netsh` 路径
- MTU 仍为 1400（`netsh ... mtu=1400 store=active`）

### Windows 路由对齐官方

- 资源路由改用 IPHLPAPI：
  - `CreateIpForwardEntry` 写入；
  - `GetIpForwardTable` 查重与回读；
  - `DeleteIpForwardEntry` 清理。
- 路由字段：`NextHop = VIP-1`、`IfIndex = Wintun 接口`、`Metric = 1`、类型 `INDIRECT`、协议 `NETMGMT`
- 查重与回读按 `Dest / Mask / NextHop / IfIndex` 四元组精确比较：
  - 四元组已存在：复用；
  - 同网段在其它接口：不接管；
  - 本接口直连/本机/广播路由：保护，不改写；
  - 本接口旧 on-link 路由：删除后按 VIP-1 重建。
- 移除批量 `cmd /D /C "route ADD ..."` 与批量 PowerShell `New-NetRoute`
- `CreateIpForwardEntry` 失败时删除同网段旧条目重试一次，仍失败回退单条 `route add`
- Windows 7 不走 IPHLPAPI，保持 `route print` + `route add`
- 旁路路由仍使用一次 `route print -4` 同时读取活动路由与默认网关

### 文案与协议

- 清理失效的中英文词条；`errorText` 测试同步为当前 `netsh` 配址路径
- `docs/PROTOCOL.md` 同步 Windows 路由形态：NextHop 为 VIP-1，Metric 为 1

## 安装

- Windows 安装包：`TopSAP Client_1.3.3_x64-setup.exe`，支持 `/S` 静默安装
- Windows ARM64：`TopSAP Client_1.3.3_arm64-setup.exe`
- Windows 便携版：保留 `resources/wintun.dll` 相对路径，以管理员身份运行
- macOS：首次启动或 helper 版本升级后按提示重新授权 root helper；未签名与公证，首次打开需处理 Gatekeeper
- Linux：需 `sudo /usr/bin/topsap-client` 启动；普通用户双击会弹窗提示

## 已知限制

- Windows 路由写入目前只完成 API 读取测试；`CreateIpForwardEntry` / `DeleteIpForwardEntry` 需连接真实网关验证
- 路由 Metric 保持 1，与官方客户端的 25/50 不同；NextHop 已对齐 VIP-1
- 自动重连当前只重新建立 TLS，不会重新注入路由或重配地址/DNS；上行泵仍绑定旧隧道句柄的问题待单独修复
- 断开时 Wintun 适配器只关闭会话/句柄，不删除网卡；地址与 DNS 保留在适配器上，下次连接覆盖
- macOS v1.3.2 修复仍需真机回归；其余限制同 v1.3.2：仅支持 `ngvone` / `cipher_type=0` 网关；TUN / 透明代理无法使用系统代理绕过；英文模式下的网关动态 `ErrMsg` 仍可能显示中文原文
