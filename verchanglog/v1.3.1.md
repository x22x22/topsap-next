# v1.3.1

发布日期：2026-11-05

## 概述

TopSAP Client v1.3.1 是 v1.3.0 之后的修复版本。本版处理 macOS 真机复测发现的两项残留问题：DNS 末尾追加了链路本地 IPv6，以及路由实际已生效但日志误报「未生效」。同时把版本检查补成可手动触发，点击侧栏版本号即可检查，并区分「无更新」与「检查失败」。Windows 与 Linux 的网卡、路由、DNS 数据面实现未改动。

## 新增

### 手动检查更新

- 点击侧栏版本号重新读取发布目录版本号，检查中显示旋转图标
- 有更新时打开更新弹窗；无更新时提示「已是最新版本」；网络或内容异常时提示「检查更新失败」
- 后端返回 `UpdateCheck { update, checked }`，用 `checked` 区分「无更新」与「检查失败」，避免断网时误报
- 启动时的自动检查仍保持静默，不弹错误

## 修复

### macOS DNS 排除 IPv6

- 连接后追加原 DNS 时，`scutil --dns` 同时返回的链路本地 IPv6（如 `fe80::...`）不再写入网络服务
- 只追加原 DNS 中的 IPv4 条目；账本仍保存完整原列表，断开时恢复原配置不受影响

### macOS 路由「未生效」误报

- 部分路由（如 `172.18.0.0/24`）已出现在 `netstat -rn`，日志却提示「1 条路由未生效」
- 旧判定同时要求 `route add` 返回成功且回读匹配：
  - `route add` 对已存在的相同路由会返回非零（File exists）
  - `route -n get` 直接查询网络地址时可能拿不到期望的网段路由
- 现改为：
  - 以回读结果作为唯一判定，不再要求 `route add` 成功
  - 回读使用网段内第一个主机地址（如 `172.18.0.1`），`/31`、`/32` 使用原地址
  - 首次回读失败后等待 120ms 重试一次
  - 仍失败时把 `route add` 输出附在运行日志的失败项中（最长 200 字符）

### 测试数据

- macOS 网络解析与 helper 白名单单测中的真实内网地址改为 RFC 5737 / RFC 3849 文档保留地址
- 不涉及运行时行为

- `cargo fmt --check` 通过

- `cargo test --lib` 通过：164 项
- `npx tsc --noEmit` 通过
- `npm test` 通过：4 个测试文件、40 项用例
- 浏览器预览：点击版本号可重新检查；有更新时弹窗正常；中英文提示正常
- macOS 专属分支仍需 CI 或真机确认

## 安装

- Windows 安装包：`TopSAP Client_1.3.1_x64-setup.exe`，支持 `/S` 静默安装
- Windows 便携版：保留 `resources/wintun.dll` 相对路径，以管理员身份运行
- macOS：首次启动或 helper 版本升级后按提示重新授权 root helper；未签名与公证，首次打开需处理 Gatekeeper
- Linux：需 `sudo /usr/bin/topsap-client` 启动；普通用户双击会弹窗提示

## 已知限制

- 发布目录版本当前为 `1.2.2`，低于本版 `1.3.1`；点击版本号会提示「已是最新版本」，这是正确行为
- macOS DNS 与路由回读修复需真机复测；系统命令部分无法在 Windows 上验证
- Windows 自检「配置网卡地址」偶发耗时较长的问题仍待复现；每步 60 秒超时与超时后清理已在 v1.3.0 生效
- Linux 仍未提供 polkit / root helper，GUI 需要以 `sudo` 运行整个应用
- 其余限制同 v1.3.0：仅支持 `ngvone` / `cipher_type=0` 网关；TUN / 透明代理无法使用系统代理绕过；英文模式下的网关动态 `ErrMsg` 仍可能显示中文原文
