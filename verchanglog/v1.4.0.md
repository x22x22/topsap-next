# v1.4.0

发布日期：2026-11-07

## 概述

TopSAP Client v1.4.0 是 Windows 连接稳定性与三平台诊断增强版本。本版重点修复 v1.3.3 在 Windows 上「配址轮询窗口过短」和「资源路由 Metric 过低导致全部回退」两个问题：Windows 配址改为 IPHLPAPI 直写，IPv4 属性窗口补写静态配置；Windows 7 资源路由对齐官方客户端；三平台运行日志补充日期、兜底与断开清理记录。macOS / Linux 数据面未改变，仅补充兜底日志与清理可观测性。

## 变更

### Windows 配址

- Win10/11 配址改为 IPHLPAPI：
  - `GetUnicastIpAddressTable` 查重；
  - `DeleteUnicastIpAddressEntry` 清理本接口旧地址；
  - `CreateUnicastIpAddressEntry` 写入地址并回读。
- 地址直接进入 `Preferred` 状态，跳过 `netsh` 创建地址时约 7–10 秒的 DAD/暂定等待；配址从 7–10 秒降到 1–2 秒。
- IPHLPAPI 失败时回退 `netsh`：先写入一次，再按 250ms 轮询，总预算 20 秒；第 6 秒仍无地址时重试一次 `delete+add`，不再因 6 秒短窗口提前失败。
- Win7 配址保持原有 `netsh` + 600ms 三轮路径，不引入 PowerShell。
- 地址写入成功后补写 Tcpip 接口静态配置（`EnableDHCP=0`、`IPAddress`、`SubnetMask`），修复「网络连接详细信息」有地址、但「TCP/IPv4 属性」页 IP 与掩码为空的问题，与官方客户端 `netsh ... static` 行为一致。
- `netcfg/windows.rs` 拆分为 `netcfg/windows/{mod,address}.rs`，地址配置 FFI 独立成子模块，行为不变。

### Windows 资源路由

- `CreateIpForwardEntry` 的 `Metric1` 改为 **接口 Metric + 1**：
  - 动态读取 `netsh interface ipv4 show interfaces` 的 `Met` 列；
  - 修复 Metric 低于接口 Metric 时返回 `ERROR_BAD_ARGUMENTS(160)`、导致全部路由回退 `route add` 的问题；
  - `route add` 兜底使用路由分量 1，两条路径有效跃点一致。
- `Metric2..5` 按 Windows 约定置 `0xFFFFFFFF`。
- 兜底日志附带 `CreateIpForwardEntry` 返回码，便于现场定位。
- Windows 7 资源路由对齐官方客户端：由直接 `route add` 改为优先 IPHLPAPI `GetIpForwardTable` / `CreateIpForwardEntry` / `DeleteIpForwardEntry`，失败再回退 `route add`。
- 断开清理：Windows 清理后回读路由表，记录 `route DELETE` 兜底条数、残留路由与网关旁路 `/32` 残留。

### 运行日志与断开清理

- 运行日志时间戳补充日期，格式为 `[2026-11-07 00:20:16]`。
- 新增 `NetConfig.notes` / `take_notes` 机制，引擎在配址、路由、DNS、清理后收集并输出兜底说明。
- Windows：IPHLPAPI 配址回退 `netsh`、资源路由回退 `route add`、静态配置写入失败、MTU 设置失败均写入运行日志。
- macOS：
  - 路由无对端地址回退 `route ... -interface` 写入日志；
  - 原 DNS 自动获取且 `scutil` 无结果时回退 Router 写入日志；
  - 默认网络服务缺失时回退 Wi-Fi / Ethernet 写入日志；
  - 断开清理记录接口删除→网关补删回退、路由残留与 DNS 恢复失败。
- Linux：断开清理删除后回读，记录残留路由；Linux 本身无命令级兜底，不修改系统 DNS。
- 清理失败或残留时，断开提示改为「已断开（部分网络配置未恢复，详见上方日志）」，不再错误显示「已恢复网络配置」。
- 补齐 Unix `NetConfig` 的 `take_notes`，修复 macOS / Linux 因缺少该方法导致的编译失败。

## 安装

- Windows 安装包：`TopSAP Client_1.4.0_x64-setup.exe`，支持 `/S` 静默安装
- Windows ARM64：`TopSAP Client_1.4.0_arm64-setup.exe`
- Windows 便携版：保留 `resources/wintun.dll` 相对路径，以管理员身份运行
- macOS：首次启动或 helper 版本升级后按提示重新授权 root helper；未签名与公证，首次打开需处理 Gatekeeper
- Linux：需 `sudo /usr/bin/topsap-client` 启动；普通用户双击会弹窗提示

## 已知限制

- Windows 7 的 IPHLPAPI 资源路由已完成代码对齐并有官方客户端实证，但仍需 Win7 SP1 真机回归
- 本次新增的断开清理日志与断开失败提示尚未经过真机回归
- macOS / Linux 的 Unix 兜底日志代码未在本机交叉编译，需在真机或 CI 确认
- 自动更新尚未实现：本版「前往」仍打开浏览器下载页面
- 自动重连当前只重新建立 TLS，不会重新注入路由或重配地址 / DNS；上行泵仍绑定旧隧道句柄的问题待单独修复
- 断开时 Wintun 适配器只关闭会话 / 句柄，不删除网卡；地址与 DNS 保留在适配器上，下次连接覆盖
- 仅支持 `ngvone` / `cipher_type=0` 网关；TUN / 透明代理无法使用系统代理绕过；英文模式下的网关动态 `ErrMsg` 仍可能显示中文原文
- macOS 应用未签名与公证，Gatekeeper 处理方式见安装说明
