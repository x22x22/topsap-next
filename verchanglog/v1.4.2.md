# v1.4.2

发布日期：2026-11-10

## 概述

TopSAP Client v1.4.2 是自动重连数据面修复版本。修复断线自动重连后日志显示「隧道已恢复」、网卡地址与路由仍然存在但所有内网访问不通的问题；重连成功后重新复核并补配地址、路由与 DNS，上行泵跟随新隧道。同时优化重连网关 IP 选择，优先复用登录时缓存的 IP，避免 VPN DNS 失效导致解析长时间等待。

## 修复

### 自动重连数据面

- 上行泵改为每个报文读取当前 `TunnelHandle`，重连替换句柄后自动走新隧道，修复上行仍发往旧连接的问题。
- 每条隧道使用独立取消令牌，替换时主动关闭旧隧道，避免旧 writer 任务与死连接泄漏。
- 重连成功后复核并补配网卡地址、网关 `/32` 旁路、资源路由与 DNS；路由账本按目标去重，重连不会让路由条数翻倍。
- 增加隧道代际与重连互斥：旧隧道的延迟 `Closed` 事件不再触发误重连，避免并发重连循环和僵尸「已连接」。
- 新隧道建立后 300ms 内再次断开时按本次尝试失败处理；初始连接同窗口断开自动触发重连。
- 上行发送失败增加限频日志，首次与每 1000 个记录一次。
- 优化重连日志文案，明确「网络配置已复核」「新隧道建立后立即断开」等状态。

## 优化

### 重连网关 IP

- 重连优先使用登录时缓存的 `session.gateway_ip`，直接用该 IP 建立 TLS 与旁路，不再先解析域名。
- 缓存 IP 建连失败时，才以 3 秒超时重新解析一次；IP 变化时补建旁路、更新缓存并重试一次。
- 新增 `tls::connect_ip`、`tls::resolve_ip_with_timeout` 与 `tunnel::open_at`，重连链路改为 IP 优先，避免断线后系统 DNS 仍指向 VPN DNS 导致 10~30 秒解析等待。

## 已知限制

- 重连不重新执行路由冲突预检；掉线期间其他 VPN 接管同前缀路由时，按平台现有规则跳过或失败。
- 网关若在重连时重新分配 VIP，客户端仍沿用登录时下发的 VIP；协议文档与现有实测均表明复用 `session_id` 不重新分配，仍需真机确认。
- 若缓存网关 IP 已失效且域名在 3 秒内未解析成功，本次重连尝试会失败并进入下一次退避重试。
- macOS 跨网络服务切换时，原 DNS 恢复目标以重连时的活动服务为准。
