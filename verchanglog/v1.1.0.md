# v1.1.0

发布日期：2026-11-03

## 概述

TopSAP Client v1.1.0 聚焦「连接生命周期可靠性」：补齐异常退出与系统关机时的会话补偿，新增 `-40077` 已登录自动踢出，并把 macOS 从 root GUI 改为「用户态 GUI + root 特权 helper」，使自检与建卡在保持最小权限的前提下可用。

## 新增

### 异常退出会话补偿

- 登录成功后加密记录网关、端口与 `session_id` 到 `session_guard.bin`
- 强杀、崩溃、关机或断电后，下次启动/连接前自动补注销，降低 `Ret=-40077` 单点冲突
- 正常注销成功、连接建立失败后主动注销成功时清除标记
- 标记超过 24 小时不再重试；Unix 下文件权限 `0600`

### 关机限时断开

- Windows：主窗口 `WM_ENDSESSION` 子类过程，在 Tao `process::exit` 前最多等待 2 秒完成断开与注销
- Linux/macOS：`SIGTERM` / `SIGINT` 限时断开
- macOS：`RunEvent::Exit` 作为 AppKit 终止的兜底
- 超时后交由操作系统回收 TUN 网卡与路由

### 已登录自动踢出（`-40077`）

- 按原客户端逻辑重新请求 `/vone/login/auth_param`
- 使用 `U/HASH/S_CODE` 请求 `/vone/login/user_pswd_r`，踢出旧会话并取得新 `session_id`
- 密码登录与动态验证码登录两条路径均生效
- 不依赖本地会话标记，覆盖官方客户端异常退出、当前客户端没有标记的场景
- 踢出后若网关要求动态验证码，继续复用现有短信/企业微信流程

### macOS 特权 helper

- 首次启动通过系统授权安装 root LaunchDaemon `com.topsap.next.helper`
- GUI 保持当前用户身份，helper 只提供 utun 创建与 `ifconfig`/`route` 白名单命令
- 通过 Unix socket + `SCM_RIGHTS` 把 utun fd 传给 GUI
- 自检的提权判断改为「helper 可用」，TUN、地址、路由操作均通过 helper 完成
- 修正 macOS utun 名称（必须使用内核分配的 `utunN`）与 4 字节地址族头
- 关闭 `tun` crate 的隐式路由，路由统一由清理账本注入与删除

## 改进

- 断开流程中注销请求与路由清理改为并发执行，缩短异常网络下的断开耗时
- 连接建立失败后主动注销已登录会话，避免残留会话占用单点名额
- macOS 应用不再以 root 运行 GUI，配置、日志与 WebView 数据保持用户属主
- 文档同步：README 双语、架构、协议、开发阶段更新记录

- `cargo fmt --check` 通过

- `cargo test --lib` 133 项通过
- Windows `cargo build --bin topsap-client` 通过
- macOS helper / privileged / tun 模块已用 `aarch64-apple-darwin` 目标与桩依赖完成类型检查
- 前端本轮未改动

## 安装

- Windows 安装包：`TopSAP Client_1.1.0_x64-setup.exe`，支持 `/S` 静默安装
- Windows 便携版：保留 `resources/wintun.dll` 相对路径，以管理员身份运行
- macOS：首次启动按提示授权安装 root helper；未签名与公证，首次打开需处理 Gatekeeper
- Linux：需 `sudo` 启动，安装 WebKitGTK 4.1 运行时

## 已知限制

- macOS helper 的 LaunchDaemon 安装、`SCM_RIGHTS`、utun 头、自检与真实连接仍需 Intel / Apple 芯片真机回归
- macOS helper 按首次安装的 uid 服务，不是多用户设计
- 仅支持 `ngvone` / `cipher_type=0` 网关；国密网关暂未实现
- 代理绕过的规则/全局模式仅对使用系统代理的程序生效，TUN/透明代理模式无法覆盖
- Linux 代理绕过仅支持 GNOME `gsettings`，KDE 等桌面暂未实现
- macOS / Linux 数据面尚未完成真机连接回归
- macOS 应用未做 Apple 签名与公证
